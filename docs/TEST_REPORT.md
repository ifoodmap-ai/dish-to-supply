## 9. ⚠️ 已知未完成 —— 上線前必讀

以下**不是 bug,是還沒做**。roadmap 上標為「開發中」是誠實的。

| 功能 | 現況 | 上線影響 |
|---|---|---|
| **金流(下單付款)** | 沙盒示範版 | **客人無法線上付款**。需串接金流商(綠界/藍新/PChomePay) |

| **LINE 即時通知** | 沙盒示範版 | 新訂單/出貨不會推播,需 LINE 官方帳號 Messaging API token |

### 其他需要注意的

| 項目 | 說明 |
|---|---|
| **寄件網域是 `gathertaiwan.com`** | 餐廳收到 iFoodmap 的信卻是給樂數位的網域寄來 → **容易進垃圾郵件匣、看起來像釣魚**。正式招商前建議另開 Resend 帳號用 `ifoodmap.ai` |
| **Resend 額度共用** | 同一個 Resend 帳號同時服務給樂、Realreal、ifoodmap。免費版 3,000 封/月共用,退信聲譽也互相影響 |
| **`admin@ifoodmap.ai` 有三重身分** | demo 方便,但正式營運時管理員不該同時是買方與賣方。`/admin/accounts` 已有黃色警示 |
| **好味小館是示範資料** | 5 筆訂單、6 道菜、供應商目錄 50 項都是造的。真實營運前要決定留或清 |

| 6 | 🔴 **高** | **全站沒有「忘記密碼」** —— 使用者忘記密碼就永久進不去 | 新增 `/reset-password`(申請 + 設定新密碼兩種情境) |
| 7 | 🟠 **中** | 供應商核准後把明文臨時密碼顯示在 admin 畫面,要人工用 LINE 轉達 | 改為寄邀請信讓供應商自己設密碼;寄信失敗才退回臨時密碼 |
| 8 | 🟠 **中** | **零業務通知** —— 供應商不知道有新單、餐廳不知道貨到了 | 新增 `notify` Edge Function + `order_events` trigger |
| 9 | 🟠 **中** | **訂單完全刪不掉** —— append-only 護欄讓 CASCADE 刪除失敗,連 admin 都清不掉誤建資料 | 新增 `admin_delete_order()` RPC(交易內旗標放行,直接 DELETE 仍被擋) |
