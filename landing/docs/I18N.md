# 中英雙語怎麼運作

> 2026-09-22 上線。中文是預設語系,英文是 `/en` 前綴。

## 一句話版本

**網址決定渲染哪個語系,localStorage 只決定「裸網址 `/` 要落在哪一版」。**

| 網址 | 語系 |
|---|---|
| `/`、`/restaurants`、`/suppliers`、`/cases`、`/about`、`/contact` | 中文 |
| `/en`、`/en/restaurants`、`/en/suppliers`、`/en/cases`、`/en/about`、`/en/contact` | English |

## 自動切換的規則(只有一條)

使用者第一次連到**裸網址 `/`** 時:

1. 之前按過語言鈕 → 聽他的(`localStorage['ifm.lang']`)
2. 沒按過 → 看 `navigator.languages`,`zh*` 給中文、`en*` 給英文
3. 兩者都沒有(例如只設了日文)→ 中文

命中英文就 `history.replaceState` 換到 `/en`,**不留歷史紀錄**,所以按上一頁不會被彈回來。

### 為什麼深層網址不自動轉

`/suppliers` 直接進來就是中文,不管瀏覽器設什麼。**這是刻意的**:
Googlebot 抓中文頁時會帶 `Accept-Language: en`,如果深層網址也自動轉,
中文版就會被整批踢到英文版、永遠索引不到。

想看英文版的深層頁就走 `/en/suppliers` —— 那是真實網址,分享得出去、爬得到。
邏輯在 `routing.js` 的 `applyPreferredLang()`,測試釘在 `tests/routing.test.cjs`。

## 檔案分工

| 檔案 | 負責 |
|---|---|
| `i18n.js` | 整份中英字典 + 語系偵測/記憶。UMD,node 可 `require`,所以測試跑得到 |
| `routing.js` | 網址 ↔ `{page, lang}`、canonical、hreflang、`<html lang>`、og:locale |
| `index.html` | markup 用 `{{ L.xxx.yyy }}` 綁定;`renderVals()` 把 `L` 餵給模板 |
| `vercel.json` | 12 條 rewrite(中文 5 + `/en` + 英文 5),全部指向 `/` |

### 改文案

直接改 `i18n.js` 裡 `DICT` 的值就好,markup 不用動。
**zh 與 en 的 key 結構必須完全一致** —— 少一個 key 的症狀是畫面上那行字**直接消失**
(support.js 只 `console.warn`,不會報錯),`tests/i18n.test.cjs` 有擋這件事。

### 新增一頁

1. `routing.js` 的 `pageByPath` / `pathByPage` 各加一筆
2. `vercel.json` 加兩條 rewrite(`/新頁` 與 `/en/新頁`)
3. `i18n.js` 的 `meta.pages` 補該頁的 title / description(兩個語系)
4. markup 加一個 `<sc-if value="{{ is新頁 }}">` 區塊

## 三個踩過的坑

### 1. 相對路徑在 `/en/` 之下會整個歪掉

`<script src="./support.js">` 在 `/en/suppliers` 之下 base 變成 `/en/`,
會去要 `/en/support.js` → 404 → **整個框架不載入、頁面全白**。
圖片 `assets/xxx.svg` 同理變成 `/en/assets/xxx.svg`。

中文版沒事只是因為 `/suppliers` 的 base 剛好還是 `/`,**是運氣不是設計**。
現在所有資源一律 root-absolute(`/support.js`、`/assets/…`),測試有釘。

### 2. 內部連結的 `href` 也要帶語系前綴

`onClick` 走 routing 換頁是對的,但 `href` 是**右鍵在新分頁開啟**、cmd+click、
以及爬蟲實際會走的路徑。英文頁上寫死 `href="/contact"` 會把人帶回中文站。
現在 markup 裡的內部連結一律是 `{{ hrefContact }}` 這類綁定。

### 3. `<title>` 不能放在 `<helmet>` 裡

support.js 的 helmet 把 `<link>` / `<meta>` **掛一次就不管**(所以用 JS 改它們是安全的),
但 `<title>` 進的是 live map,**每次 render 都會被重設回原始碼那行字**。
所以 `<title>` 搬到真正的靜態 `<head>`,由 `Component.syncSeo()` 依語系與頁面覆寫。
順帶好處:不跑 JS 的社群爬蟲現在讀得到標題(以前整頁沒有 `<title>`)。

## AI 採購助手

右下角的 widget 在 React 之外,沒有 state 可以重繪,所以靠事件換字:
切語系時 `Component.switchLang()` 會發 `window` 的 `ifm:langchange`,
widget 訂閱它重寫自己的靜態文字。**已經送出的對話訊息不會被回頭翻譯**(那是歷史紀錄)。

打去 `/api/ai-chat`、`/api/ai-menu`、`/api/ai-extract` 的 body 都會帶 `lang`,
主專案的 Supabase Edge Function `ai` 看到 `lang: "en"` 會讓回覆、菜單分析的品名與摘要
全部改用英文(見 `ifoodmap/supabase/functions/ai/index.ts` 的 `withLang()`)。

寫進 `landing_leads` 的 `detail` 欄位**維持中文標籤** —— 那是給台灣業務看的內部欄位,
翻了反而看不懂。
